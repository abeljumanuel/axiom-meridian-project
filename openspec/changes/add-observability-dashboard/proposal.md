## Why

Curators and admins currently have to run ad-hoc Python snippets or read raw Markdown/SQLite to understand Meridian's state — server health, indexed scopes, rule/lesson counts, pending proposals (TICKET-017 / US-H1). This sits outside the core MCP/knowledge-governance scope of the capstone and is explicitly deferred, but is valuable as an optional companion, evaluated only if time remains after the core backlog.

## What Changes

- Add a small, standalone, read-only web dashboard as a separate local process (e.g. a thin FastAPI layer that imports the existing `knowledge_consumption` functions as a library, plus a minimal frontend).
- It never speaks the MCP protocol and never performs writes.
- Include an embedding projector view: a dimensionality-reduced (2D/3D) scatter plot of existing rule/lesson embeddings, colored by scope/category/severity, so a curator can visually inspect how knowledge clusters and spot outliers or overlap — a visual complement to `redundancy-detection`'s numeric report.

## Capabilities

### New Capabilities
- `observability-dashboard`: read-only web view of Meridian's server health, scope hierarchy, rule/lesson counts, pending proposals, rendered usage manual, and an embedding projector for the existing rule/lesson vectors.

## Impact

- New process/package (dashboard API + minimal frontend)
- No changes to `meridian.db` or any `.md` file
- No new embeddings generated by the dashboard itself — the projector only reads vectors that already exist in ChromaDB
